# Student setup and Android Emulator

## Clone and prerequisites

The owner controls the initial commit/push. This repository remains Public for committee review: anyone can read it, while team write access requires the owner's approval. After the owner publishes the reviewed preparation, each student clones only:

```sh
git clone https://github.com/hetaf234/2026-GP1-1.git
cd 2026-GP1-1
```

Install the approved Flutter 3.47.5 SDK, JDK 21, Android Studio/Android SDK, Python 3.14 and Git. deployment/policy.json pins the exact Flutter revision used by automated builds. Do not upload an SDK, local.properties, cache, key or downloaded model to Git. Run `flutter doctor` and resolve Android SDK/license/device checks. Create an Android Emulator in Android Studio Device Manager and start it. `flutter devices` should list it.

Android wrapper scripts/JAR and local.properties are generated by the pinned Flutter tooling and excluded from Git. Use the Flutter commands below rather than assuming a checked-in ./gradlew. The Gradle distribution is selected by android/gradle/wrapper/gradle-wrapper.properties and downloaded from the official Gradle source as needed.

```sh
cd frontend
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
```

## Current development connection

The backend remains private. A teammate with approved cloud invocation access runs this on their own computer:

```sh
gcloud run services proxy misbar-consolidated-test-20261101 --project=project-51f11627-cb56-4c1e-978 --region=us-central1 --port=8080
```

Existing access is required; this command does not grant it. Use authorized accounts and do not share a cloud credential file. If access is missing, ask the owner to review a narrow grant separately. On Android Emulator, 10.0.2.2 reaches the host computer:

```sh
cd frontend
flutter run --flavor misbar2 --dart-define=MISBAR_SECOND_COPY=true --dart-define=MISBAR_API_BASE_URL=http://10.0.2.2:8080
```

The phone's 127.0.0.1 with ADB reverse is different from the emulator host address. Never silently fall back to a laptop address when a configured HTTPS API fails. The existing client tests enforce that behavior. Wireless physical-phone connectivity remains unimplemented; see BACKEND_CONNECTIVITY.md.

## Tests without cloud credentials

From the root, create a local Python virtual environment and install deployment/test-requirements.txt under the checked-in constraints. Run `python deployment/run_checks.py --backend`. This denies external network access and uses mocks. The local Firestore emulator command is in security_tests/README.md and targets demo-misbar-metadata only. No migration or paid scan is part of setup.

Use the separate offline Flutter preview for UI work; frontend/README.md gives its exact flags. A developer's own debug key may differ from the owner's approved signing key. Use a fresh development AVD for local builds, and a separate distribution-testing AVD for approved signed APKs; never replace or uninstall the owner's physical application to make development builds install.
